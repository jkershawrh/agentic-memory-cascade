# Agentic Memory Cascade

Agentic Memory Cascade is a focused proof that consequential information learned in one
agent session can be curated by [Cascade Compression](https://github.com/jkershawrh/cascade-compression)
and recalled by a fresh session later.

This repository is intentionally a thin consumer of Cascade Compression v0.1.0. It does
not contain a second copy of the compression engine.

## What the proof establishes

The bundled synthetic incident handoff runs two conditions against the same fresh session:

- **Control:** memory is disabled. The deterministic agent scores 0/3.
- **Treatment:** Cascade-curated memory is supplied. The agent must recall the incident
  cause, operational constraint, and resolution, scoring 3/3 with no unsupported claims.

Session one sends 15 observations through Cascade. Twelve routine acknowledgements are
compressed and three consequential facts become memory. Session two has a distinct session
identity and recalls those facts.

The claim is deliberately narrow: **memory remains available across agent sessions in one
running process.** Restart durability, production readiness, governance, and long-term
storage are not demonstrated by this release.

The synthetic fixture explicitly marks consequential observations with severity. This
proves the session-to-memory-to-recall seam; it does not prove that the system autonomously
learned which incident facts matter.

## Run it

Python 3.9 or newer is required.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
agentic-memory-proof
```

The command writes the evidence report to standard output and exits nonzero if the proof
fails. To retain a local report in the gitignored results directory:

```bash
agentic-memory-proof --output results/proof.json
```

For the presentation-friendly view, run:

```bash
./demo.sh
```

This prints the compact session handoff and score while retaining the complete JSON report
under `results/proof.json`.

For an optional presentation-only answer generated by local Ollama:

```bash
agentic-memory-proof \
  --ollama-url http://localhost:11434 \
  --ollama-model granite3.2:8b-instruct
```

Ollama output is recorded under `illustrative_answers`; it never contributes to the
deterministic pass/fail score.

## Local API

```bash
make up
```

The service exposes:

- `POST /v1/sessions`
- `POST /v1/sessions/{session_id}/observations`
- `POST /v1/sessions/{session_id}/recall`
- `POST /v1/proof/run`
- `GET /health`

## Architecture seam

```text
Session A observations
        ↓
Cascade Compression — suppress routine chatter, retain consequential survivors
        ↓
Bounded MemoryArchive + RecallEngine
        ↓
Session B receives relevant facts
        ↓
Deterministic A/B evidence
```

See [the presentation brief](docs/presentation-brief.md) for the story and demonstration
sequence intended for the agentic engineering group.

## Safety and repository boundary

All bundled data is synthetic. Generated reports, deployment material, credentials, raw
agent conversations, and environment identities are excluded from Git. Run `make boundary`
before publishing changes.
